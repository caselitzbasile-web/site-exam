01

REMONTONS LE TEMPS

La timeline du Web

Internet est le réseau qui relie les appareils. Le Web est un service qui utilise Internet pour consulter des pages et des applications avec un navigateur. Au fil du temps, il est devenu un espace pour apprendre, discuter, partager des vidéos et jouer.

Cette timeline présente quelques repères : elle ne raconte pas toute l’histoire du Web. Facebook, par exemple, n’est pas le premier réseau social.

  1. 1989
    Naissance du Web

    Une idée au CERN

    Tim Berners-Lee propose un système pour partager des informations grâce à des liens entre documents. C’est le point de départ du World Wide Web.

    Source : CERN — La naissance du Web

  2. 1990
    Premiers outils

    Le premier navigateur et le premier serveur

    Tim Berners-Lee développe le premier navigateur-éditeur et le premier serveur web. Le premier site présente le projet World Wide Web.

    Source : CERN — Histoire du Web

  3. 1991
    Diffusion

    Le projet s’ouvre à d’autres utilisateurs

    En août, le logiciel du Web est annoncé dans des groupes de discussion sur Internet. L’intérêt pour le projet se développe au-delà du CERN.

    Source : CERN — Histoire du Web

  4. 1993
    Ouverture

    Un Web librement utilisable

    Le 30 avril, le CERN place le logiciel du Web dans le domaine public. Le navigateur Mosaic contribue également à populariser le Web grâce à son interface graphique.

    Sources : CERN — La naissance du Web et Histoire du Web

  5. 1994
    Standards

    La création du W3C

    Tim Berners-Lee fonde le World Wide Web Consortium. Son rôle est de développer des standards communs pour favoriser un Web utilisable sur différents outils.

    Source : W3C — Histoire du consortium

  6. 2001
    Jeux vidéo

    RuneScape : un monde à explorer dans le navigateur

    RuneScape est lancé le 4 janvier 2001. Ce jeu de rôle en ligne permet à des joueurs de se retrouver dans un univers de fantasy. À ses débuts, il est jouable dans un navigateur grâce à la technologie Java.

    Ce que cela illustre : le navigateur peut accueillir un jeu multijoueur, et pas seulement afficher des documents. RuneScape n’est toutefois pas le premier jeu sur le Web.

    Sources : Jagex — Lancement de RuneScape et Jagex — Origines du projet

  7. 2004
    Réseaux sociaux

    Facebook relie les personnes

    Facebook est lancé le 4 février 2004, initialement pour les étudiants de Harvard, sous le nom « TheFacebook ». Le service s’ouvre ensuite à un public plus large.

    Le principe : créer un profil, établir des contacts et partager des publications. Les utilisateurs produisent eux-mêmes une partie du contenu du Web.

    Source : Meta — Histoire de Facebook

  8. 2005
    Vidéos et communautés

    YouTube : publier et partager des vidéos

    Le 23 avril 2005, la première vidéo de YouTube, « Me at the zoo », est publiée. La plateforme permet de partager des vidéos et de former des communautés autour de chaînes.

    Le lien avec les jeux vidéo : les vidéos peuvent servir à montrer une partie, expliquer une stratégie ou apprendre à jouer. Regarder une vidéo de jeu sur le Web est différent de jouer directement dans le navigateur.

    Source : YouTube — La première vidéo

  9. 2010
    Réseaux sociaux et mobile

    Instagram met les images au premier plan

    Instagram apparaît le 6 octobre 2010. Le service se développe d’abord comme une application mobile centrée sur le partage de photos.

    À comprendre : les réseaux sociaux ne se limitent pas aux sites web. Ils peuvent aussi être accessibles par des applications installées sur un téléphone. Une application connectée utilise Internet, mais son interface n’est pas forcément une page web.

    Source : Meta — Les débuts d’Instagram

  10. 2011
    Jeux vidéo et 3D

    WebGL ouvre la porte à la 3D sans plugin

    Le 3 mars 2011, le groupe Khronos publie la spécification WebGL 1.0. Cette technologie permet d’utiliser l’accélération graphique pour afficher de la 3D dans le navigateur, sans installer de plugin.

    Pour les jeux : JavaScript et WebGL permettent de créer des scènes interactives en 3D. WebGL est un outil graphique, pas un jeu en lui-même.

    Source : Khronos — Publication de WebGL 1.0

  11. 2014
    Multimédia et jeux

    HTML5 franchit une étape de standardisation

    Le 28 octobre 2014, le W3C publie HTML5 comme recommandation. Cela marque une étape importante : certaines fonctionnalités existaient déjà dans les navigateurs avant cette date.

    Avec JavaScript et les API du navigateur, la plateforme web permet de combiner dessins, vidéos, sons et interactions. Pour un jeu, Canvas peut servir à dessiner en 2D et WebGL à afficher de la 3D.

    Sources : W3C — Recommandation HTML5 et MDN — Développement de jeux

  12. 2020–2021
    Fin d’une technologie

    La fin de Flash Player

    Flash a servi à diffuser des animations et des jeux dans le navigateur avec un plugin. Adobe arrête le support de Flash Player le 31 décembre 2020, puis bloque l’exécution des contenus dans Flash Player à partir du 12 janvier 2021.

    Les technologies modernes comme HTML, JavaScript et WebGL permettent de créer de nouvelles expériences sans Flash. Un ancien jeu Flash ne devient cependant pas automatiquement un jeu HTML5 : il faut le porter ou utiliser une solution de préservation.

    Sources : Adobe — Fin de Flash Player et MDN — Développement de jeux

  13. Aujourd’hui
    Des usages variés

    Apprendre, échanger, créer et jouer

    Le navigateur peut afficher un cours, ouvrir un réseau social ou faire fonctionner un jeu. Ces usages reposent sur des technologies web, avec des enjeux de performance, d’accessibilité et de protection des données.

    Pour approfondir : les standards et la sécurité web.

À retenir : Internet et Web ne sont pas synonymes

Un jeu dans le navigateur utilise les technologies du Web. Un jeu installé sur ordinateur ou console peut utiliser Internet pour le multijoueur sans passer par une page web. De même, un réseau social peut proposer un site et une application mobile.

Qu’est-ce qu’un réseau social ?

C’est un service qui permet de créer des relations et d’échanger des contenus avec d’autres utilisateurs : messages, photos, vidéos ou commentaires. Les profils, abonnements et communautés organisent ces échanges.

Avant de publier, réfléchis à qui pourra voir ton contenu. Vérifie aussi les informations que tu partages.

HTML5 est-il un moteur de jeu ?

Non. « Jeu HTML5 » est une expression souvent utilisée pour parler d’un jeu construit avec les technologies modernes du Web. HTML organise la page ; JavaScript programme les actions ; Canvas ou WebGL peuvent afficher les graphismes.

Un moteur ou une bibliothèque de jeu peut aider à gérer les animations, les collisions et les scènes.

LIRE UNE ADRESSE

Qu’est-ce qu’une URL ?

Une URL, pour Uniform Resource Locator, est une adresse qui indique où trouver une ressource et comment y accéder. Elle peut désigner une page, une image ou un fichier.

https://cours.example.org/web?niveau=debutant#quiz
https

Le protocole

Il indique comment communiquer. HTTPS utilise TLS pour protéger les échanges.

cours.example.org

Le nom d’hôte

Il identifie le serveur visé. Ici, « cours » est un sous-domaine de « example.org ».

/web

Le chemin

Il désigne une ressource sur le serveur. Il ne correspond pas forcément à un fichier réel.

?niveau=debutant

Les paramètres

Ils transmettent des informations, par exemple un filtre ou une recherche.

#quiz

Le fragment

Il peut pointer vers une partie de la page. Il n’est pas envoyé au serveur dans la requête HTTP.

À toi de jouer : décompose une URL

Utilise l’exemple ou saisis une adresse complète. L’analyse se fait dans ton navigateur, sans visiter le site.

DES NOMS FACILES À RETENIR

Les noms de domaine

Un nom de domaine est un nom lisible par les humains. Le DNS, ou Domain Name System, permet notamment de retrouver les adresses IP associées à ce nom.

cours Sous-domaine
.
example Nom choisi
.
org Extension (TLD)

Le rôle du DNS

Imagine un annuaire : tu connais un nom, il aide ton appareil à retrouver une adresse. Un même nom peut être associé à plusieurs adresses IP.

Les extensions

« .be » et « .fr » sont liées à des pays. « .com » et « .org » sont des extensions génériques. Une extension ne garantit pas la fiabilité d’un site.

L’enregistrement

Un domaine s’enregistre auprès d’un bureau d’enregistrement. Il faut généralement le renouveler. Le domaine et l’hébergement sont deux services distincts.

Est-ce que « www » est obligatoire ?

Non. « www » est un sous-domaine utilisé par convention. Un site peut fonctionner sans lui. Les adresses avec et sans « www » peuvent être configurées pour renvoyer vers le même site.

Un nom de domaine et une URL, est-ce la même chose ?

Non. Dans « https://example.org/cours », le domaine est « example.org ». L’URL complète contient aussi le protocole et le chemin.

DES RÈGLES COMMUNES

Les standards du Web

Les standards définissent des règles communes pour que les technologies du Web fonctionnent ensemble. Ils favorisent la compatibilité entre navigateurs, même si des différences peuvent subsister.

HTML

La structure

Décrit le sens et l’organisation du contenu : titres, paragraphes, liens et formulaires. 

<h1>Bonjour le Web !</h1>

Le HTML Living Standard est maintenu par le WHATWG.

CSS

La présentation

Définit les couleurs, la mise en page, les espacements et l’adaptation aux écrans. 

h1 { color: #023047; }

Les spécifications CSS sont développées au W3C.

JavaScript

Les interactions

Permet de réagir aux actions : corriger un quiz ou analyser une adresse. 

button.addEventListener(
  "click", afficherResultat
);

Le langage repose sur le standard ECMAScript d’Ecma International.

Un Web accessible à davantage de personnes

Les WCAG du W3C donnent des recommandations d’accessibilité : contrastes lisibles, navigation au clavier, textes alternatifs pour les images et champs de formulaire bien étiquetés.

05

LES BONS RÉFLEXES

La sécurité web

La sécurité repose sur les protections techniques et sur nos habitudes. Voici quelques réflexes utiles.

01 · Connexion

Comprendre HTTPS

HTTPS protège les données pendant leur transport et aide à authentifier le serveur. Un site frauduleux peut aussi utiliser HTTPS : cela ne garantit pas l’honnêteté du site.

02 · Comptes

Protéger ses accès

Utilise des mots de passe longs et uniques, un gestionnaire de mots de passe et l’authentification à plusieurs facteurs quand elle est disponible.

03 · Messages

Repérer le phishing

Le phishing, ou hameçonnage, cherche à te tromper en imitant un organisme. Méfie-toi des demandes urgentes et vérifie l’adresse avant de communiquer des informations.

04 · Appareils

Garder ses outils à jour

Les mises à jour corrigent notamment des failles. Mets à jour ton navigateur et ton système, et conserve des sauvegardes de tes fichiers importants.

Le piège du nom rassurant

Observe cette adresse fictive :

https://banque.example.org.connexion.example.net
Quel est le domaine enregistrable ici ?

C’est example.net. « banque.example.org.connexion » est placé devant comme sous-domaines. La présence d’un nom familier au début ne prouve pas que tu es sur le bon site.

En cas de doute, ouvre directement le site officiel avec une adresse connue ou un favori.
